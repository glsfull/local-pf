# local-pf

## Веб-панель мониторинга позиций

Панель хранит проекты, ключевые фразы и историю проверок в локальной базе
SQLite. Она запускается на Python 3.11 или новее.

```powershell
py -m pip install -r requirements.txt
py -m dashboard
```

Откройте [http://127.0.0.1:8080](http://127.0.0.1:8080). Первый запуск создаёт
пустую SQLite-базу `.local-pf/dashboard.sqlite3`. Панель слушает только
`127.0.0.1` и выполняет одну проверку за раз. Параметры `--port` и `--db`
позволяют выбрать порт и файл базы.

В разделе «Проекты» добавьте адрес сайта, интервал в секундах и ключевые
фразы. При необходимости укажите код региона Яндекса. Для каждой фразы
выберите один тип подсказки — бренд или домен без зоны. Релевантный URL
ограничивает поиск заданной страницей. Если поле пустое, подходят страницы
проекта и его поддоменов.

Подготовьте контейнер `dp-agent` по этапу 1 и держите
[http://localhost:56565](http://localhost:56565) открытым во время прогона.
Кнопка «Снять позиции» запускает `agent.py` в контейнере на `DISPLAY=:1`.
Агент читает снимок фраз из общей базы SQLite и разбирает HTML-выдачу в Chromium.
На запрос проверяются до пяти страниц и до 50 органических результатов.
Если целевая страница за пределами этого диапазона, агент проверяет уточнённый
запрос. Интервал отсчитывается после проверки всей фразы. При SmartCaptcha,
ошибке доступа или нераспознанной выдаче агент завершает проверку с кодом 1
и сохраняет уже собранные позиции.

Для настроек парсера используйте `.env.example`. `LOCAL_PF_OBSERVATION_DELAY`
задаёт паузу в секундах перед открытием страницы выдачи. При запуске панели
из папки проекта база и логи доступны в контейнере под `/app`. Если
`--db` или `--agent-log-dir` указывает за пределы папки проекта, подключите
этот путь к контейнеру и передайте соответствующий путь через `--container-db`
или `--container-log-dir`. Для Linux с локальным экраном `:1` можно запустить
панель с `--local-agent`. Проверку конкретного проекта можно запустить напрямую,
подставив его идентификатор из адреса в панели.

```powershell
docker exec -e DISPLAY=:1 dp-agent /opt/local-pf/bin/python /app/agent.py --project-id 1
```

«Ключевики» показывают текущие позиции и показатели фраз. Частотность,
спрос, вероятность попадания в топ, мощность, конкуренцию, план переходов
и бюджет можно внести в форму проекта. В этой же форме фразы распределяются
по кластерам. «Кластеры» показывают суммарную частотность и позволяют
указать целевой URL, оценку коммерции, наличие метаданных и текста.

«Позиции» содержат график в процентах и количестве, матрицу последних
30 дат измерений и детали каждой проверки. Исходный и уточнённый запросы
хранятся раздельно. `51+` означает, что страница отсутствует в проверенном
диапазоне, прочерк означает отсутствие измерения.

Из деталей проверки доступен её журнал в SQLite. Раздел «Логи» показывает
последний `report.json` из `logs/` или из папки, заданной `LOG_DIR`
или `--agent-log-dir`. Даты и время отображаются по Москве (МСК, UTC+3).

Отдельный демо-режим использует пример выдачи и временную базу.

```powershell
python -m examples.dashboard_demo
python -m unittest discover -s tests -p test_dashboard.py -v
```

## Браузерная диагностика страниц

Диагностический запуск с `config.yaml` проверяет доступные ссылки через
Chromium. Агент открывает `ya.ru`,
отправляет запрос кнопкой «Найти» и открывает целевой сайт кликом по результату
выдачи. Ссылки на проверяемые страницы он ищет на странице, открытой из выдачи.
При появлении SmartCaptcha агент завершает проверку с кодом 1 и записывает
`captcha_encountered: true` в отчёт.

## Этап 1. Проверьте контейнер и Chromium

Начните с этого этапа. Выполните команды в PowerShell из папки проекта.

```powershell
docker ps --filter name=dp-agent
docker inspect dp-agent --format '{{json .Mounts}}'
```

Если папка проекта уже подключена к `/app`, используйте существующий контейнер.
Если он остановлен, запустите его командой `docker start dp-agent`.
Если монтирования нет, сохраните старый контейнер под другим именем и создайте
новый с монтированием. Если контейнера ещё нет, выполните только присваивание
`$Project` и команду `docker run`. Откройте `http://localhost:56565` для наблюдения
за браузером.

```powershell
$Project = (Get-Location).Path
docker stop dp-agent
docker rename dp-agent dp-agent-backup
docker run -d --name dp-agent --init -p 127.0.0.1:56565:80 --mount "type=bind,source=$Project,target=/app" qiudeng/drissionpage4-ubuntu-webdesktop-novnc
```

В проверенном образе команда `python3` запускает Python 3.8. Установите Python 3.11
в отдельное окружение и добавьте зависимости из `requirements.txt`. Окружение
хранится в контейнере и сохраняется при его обычном перезапуске. Если
`/opt/local-pf/bin/python` уже есть, начните с проверки версии и запуска примера.
[Описание образа](https://hub.docker.com/r/qiudeng/drissionpage4-ubuntu-webdesktop-novnc),
[установка Python через uv](https://docs.astral.sh/uv/guides/install-python/).

```powershell
docker exec dp-agent curl -fsSL -o /tmp/local-pf-uv-install.sh https://astral.sh/uv/0.13.9/install.sh
docker exec -e UV_UNMANAGED_INSTALL=/opt/local-pf-tools dp-agent sh /tmp/local-pf-uv-install.sh
docker exec -e UV_PYTHON_INSTALL_DIR=/opt/local-pf-python dp-agent /opt/local-pf-tools/uv venv --no-cache --python 3.11 /opt/local-pf
docker exec dp-agent /opt/local-pf-tools/uv pip install --no-cache --python /opt/local-pf/bin/python -r /app/requirements.txt
docker exec dp-agent /opt/local-pf/bin/python --version
docker exec -e DISPLAY=:1 dp-agent /opt/local-pf/bin/python /app/examples/hello_world.py --local
$LASTEXITCODE
```

**Условие перехода.** PowerShell показывает Python 3.11 или новее, результат
`local-pf Chromium check` и код `0`. Контрольная страница встроена в пример.
Если проверка завершилась ошибкой, проверьте монтирование `/app`, наличие
зависимостей, значение `DISPLAY` и путь `CHROME_PATH`.

## Этап 2. Подготовьте один контрольный сценарий

В обычном браузере выберите запрос, по которому целевой домен уже виден в
выдаче. Убедитесь, что страница, открываемая из выдачи, содержит ссылку на
одну нужную страницу. Запишите эту пару в `config.yaml`.

- `SEARCH_KEYWORD` задаёт запрос, `TARGET_DOMAIN` задаёт домен без схемы и пути.
  Поддомены этого домена тоже подходят.
- `TARGET_PAGES` принимает пути вида `/about`, точные тексты ссылок и объекты с
  одним из полей `url`, `text`, `selector`. Для объекта можно добавить
  `expected_selector` с CSS-селектором ожидаемого элемента. По умолчанию
  агент проверяет видимость `h1`.
- `SEARCH_INPUT_SELECTOR`, `SEARCH_BUTTON_SELECTOR`, `RESULT_LINK_SELECTOR` и
  `CAPTCHA_SELECTOR` задают CSS-селекторы для текущей версии страниц поиска.
  `TIMEOUT_SECONDS` ограничивает ожидание отдельных операций браузера.
- `OBSERVATION_DELAY_SECONDS` задаёт фиксированную паузу перед видимыми
  действиями в диапазоне от 0 до 5 секунд. Значение по умолчанию — 0,7 секунды.
  Значение 0 отключает паузу. В режиме `--headless` паузы наблюдения отключены.

При необходимости скопируйте `.env.example` в `.env` и укажите путь к Chromium
через `CHROME_PATH` или папку отчётов через `LOG_DIR`. Системные переменные
окружения имеют приоритет. По умолчанию браузер берётся из `PATH`, а отчёты
попадают в `/app/logs`.

**Условие перехода.** Известны запрос, ожидаемый домен, ссылка на проверяемую
страницу и видимый элемент, подтверждающий её загрузку.

## Этап 3. Проверьте поиск, переход и отчёт

Запустите агент одной командой. Держите http://localhost:56565 открытым во
время прогона. В контейнере Chromium отображается на `DISPLAY=:1`. Агент
записывает отчёт до закрытия окна.

```powershell
docker exec -e DISPLAY=:1 dp-agent /opt/local-pf/bin/python /app/agent.py
$LASTEXITCODE
Get-Content .\logs\agent.log -Encoding UTF8 -Tail 30
Get-Content .\logs\report.json -Encoding UTF8 -Raw | ConvertFrom-Json
```

Код 0 означает, что агент дошёл до целевого сайта и завершил проверку списка.
Результаты в `pages_checked` содержат URL, статус, последнюю измеренную
позицию прокрутки, ошибку и время МСК. В `events` записаны операции, URL,
проверенные селекторы и измерения прокрутки. Все записи доступны в панели
через раздел «Логи». Код 1 означает
ошибку выполнения, отсутствие сайта в выдаче или остановку на ограничении
доступа. При этих остановках отчёт сохраняет результаты, собранные к этому моменту.

**Условие перехода.** В noVNC видны отправка формы и переход по клику из выдачи.
В отчёте `search_result_found: true` и результат контрольной страницы
`exists: true` со статусом `OK`.

| Результат первого запуска | Действие |
| --- | --- |
| `captcha_encountered: true` или ошибка доступа | Остановите прогоны и сохраните отчёт и последние строки журнала. Для диагностики проверок страниц используйте локальные тесты следующего этапа. |
| В журнале «Форма поиска отсутствует» | Сверьте `SEARCH_INPUT_SELECTOR` и `SEARCH_BUTTON_SELECTOR` с доступной формой. |
| `search_result_found: false` и в журнале нет ошибки доступа | Сверьте запрос и домен с выдачей. Команда с `--debug` покажет, какие домены найдены по `RESULT_LINK_SELECTOR`. |
| `search_result_found: true`, у страницы `NOT_FOUND` | Проверьте ссылку на входной странице и наличие видимого `expected_selector` после перехода. |

## Этап 4. Проверьте ошибки и несколько страниц

Автоматические сценарии используют локальный HTTP-сервер и настоящий Chromium.
Их можно запустить сразу после этапа 1, если этап 3 остановился на ограничении
доступа. Добавляйте остальные страницы в рабочий сценарий после прохождения
этапа 3.

```powershell
docker exec -w /app dp-agent /opt/local-pf/bin/python -m unittest discover -s tests -v
```

**Условие перехода.** Тесты проходят. Для рабочего списка страниц в отчёте
присутствует отдельная запись по каждой проверке и журнал объясняет сбои.

## Этап 5. Соберите результаты приёмки

После этапов 3 и 4 зафиксируйте результаты 10–20 сценариев на разрешённых
запросах и сайтах. Для каждого сохраните код выхода, отчёт и наблюдение по
переходу в noVNC. Сохраняйте результаты сразу после каждого запуска, поскольку
`report.json` заменяется. При ограничении доступа завершите серию и запишите
фактическое число выполненных сценариев.

**Текущий статус.** Код поиска, клика, проверки страниц и отчётности уже есть.
На ПК с Docker Desktop следующий шаг — команда `hello_world.py --local` на
этапе 1. После неё подготовьте один сценарий и проверьте живой переход на
этапе 3. Результаты и открытые критерии ТЗ перечислены в
[отчёте о проверке](TESTING.md).
