# Доработанное ТЗ (issue #12)

Документ уточняет [исходное ТЗ](../Техническое%20задание) и задание из
[issue #12](https://github.com/glsfull/local-pf/issues/12). В нём перечислены
требования, способ их реализации, проверка и пункты, которые не реализованы,
с причинами. Дизайн и структура панели повторяют ТопПульт (issue #9): шапка
с балансом, меню «Инструменты», проекты, вкладки «Ключевики» и «Позиции».

## 1. Цель

Локальная панель на Windows управляет браузерным агентом в Docker-контейнере
`dp-agent` и снимает позиции сайта в Яндексе. Агент открывает ya.ru, вводит
фразу, нажимает «Найти», ищет сайт проекта в топ-50 и переходит на него
кликом по результату. Всё, что делает браузер, видно в noVNC. Позиции для
отчётов берутся из Yandex Search API, а не из браузера.

## 2. Границы проекта

Реализуется то, что измеряет и показывает видимость сайта, и прозрачная для
оператора работа браузера. Не реализуется то, что подделывает поведенческие
сигналы Яндекса или действия пользователей на чужих сайтах:

| Пункт исходного ТЗ | Решение | Причина |
| --- | --- | --- |
| «Цифровой след» на сайте: 30–45 с, скроллы, клики, паузы для поиска | Не реализован | Имитация визитов, чтобы повлиять на поведенческие факторы ранжирования, — накрутка. Она нарушает [условия Яндекса](https://yandex.ru/support/webmaster/ru/yandex-indexing/webmaster-advice), и сайт за неё могут понизить в выдаче. |
| Конверсии: корзина, форма обратной связи, регистрация со случайными данными | Не реализованы, чекбоксов в панели нет | Фиктивные заявки и регистрации засоряют CRM и аналитику владельцев сайтов, искажают их метрики и могут оплачиваться как лиды. Кнопки для несуществующей функции в панели нет. Пример конфигурации отклоняет ключ `conversions` и объясняет причину. |
| Автоматическое решение чекбокса SmartCaptcha | Не реализовано | Капча — защита Яндекса от автоматических запросов. Агент останавливается, и капчу решает оператор (раздел 6). |
| Маскировка автоматизации: «плавные движения мыши, случайные паузы, посимвольный ввод» | Не реализована | Такая эмуляция нужна только для обхода антибот-защиты. Агент вводит фразу и делает видимые паузы наблюдения (`OBSERVATION_DELAY_SECONDS`, 0–5 с), чтобы оператор видел шаги в noVNC. |

## 4. Пользовательский сценарий

1. `py -m dashboard` — панель откроется в браузере, контейнер `dp-agent` запустится.
2. «Инструменты → Настройки панели»: `YANDEX_API_KEY`, `YANDEX_FOLDER_ID`,
   источник позиций и адрес noVNC. Вместо этого шага можно выполнить
   `py -m dashboard --config panel.yaml`.
3. «Создать проект»: адрес сайта, регион, ключевые фразы и тип уточнения
   для каждой фразы.
4. Вкладка «Позиции» → «📸 Снять позиции». Панель отправляет отложенные
   запросы в Search API и показывает позиции в матрице и на графике.
5. «🚀 Запустить агента» → страница «Агент» со статусом и журналом;
   «Открыть noVNC» показывает браузер.
6. При капче статус станет «Капча — ожидание оператора». Решите капчу в
   noVNC или нажмите «Продолжить».

## 5. Search API

- Запрос: `POST https://searchapi.api.cloud.yandex.net/v2/web/searchAsync`,
  заголовок `Authorization: Api-Key <YANDEX_API_KEY>`, тело содержит
  `folderId`, `query.searchType: SEARCH_TYPE_RU`, `query.queryText`, `region`,
  `groupSpec.groupMode: GROUP_MODE_DEEP`, `groupsOnPage: 50`, `docsInGroup: 1`,
  `responseFormat: FORMAT_XML`.
- Ответ — операция. Панель опрашивает
  `GET https://operation.api.cloud.yandex.net/operations/<id>` до `done: true`
  и декодирует `response.rawData` (base64, XML). Код ошибки 15 означает, что
  результатов нет.
- Позиция — номер первого документа, домен которого совпадает с сайтом проекта
  или его поддоменом. Если задан релевантный URL, учитывается только он.
- Документация: [searchAsync](https://aistudio.yandex.ru/docs/ru/search-api/api-ref/WebSearchAsync/search),
  [операции](https://yandex.cloud/ru/docs/api-design-guide/concepts/operation),
  [тарифы](https://aistudio.yandex.ru/docs/ru/search-api/pricing).

## 6. Капча

Агент проверяет `CAPTCHA_SELECTOR` после каждой загрузки выдачи. Если капча
найдена:

1. Статус меняется на «Капча — ожидание оператора», в журнал пишется событие «Капча».
2. Агент каждые 2 с проверяет, исчезла ли капча и нажата ли «Продолжить».
3. После этого агент повторяет поиск той же фразы.
4. Если капча не решена за 15 минут или появилась 3 раза подряд, запуск
   завершается со статусом «Ошибка».

## 7. Ограничения и непроверенное

- Работа с настоящим Yandex Search API, живой выдачей ya.ru и Docker Desktop на
  Windows не проверена: для этого нужны ключ Yandex Cloud и ПК с Docker.
  Протокол API проверен тестами по документации с подменой HTTP-ответов.
  Поиск, листание и клик проверены в настоящем Chromium на локальной копии
  разметки выдачи.
- Отложенные операции хранятся в памяти панели. Если перезапустить панель во
  время проверки через API, проверка отмечается прерванной, ответы теряются,
  а уже оплаченные запросы не используются.
- `GROUP_MODE_DEEP` даёт один документ на сайт, поэтому позиция в API может
  отличаться от позиции в браузере, где видны несколько страниц одного сайта.
- Селекторы выдачи (`RESULT_LINK_SELECTOR`, `NEXT_PAGE_SELECTOR`,
  `CAPTCHA_SELECTOR`) задаются в `config.yaml`. Если Яндекс изменит разметку,
  их нужно обновить.
