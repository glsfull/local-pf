# Отчёт о проверке local-pf

## Проверка для PR №11

Интерфейс в стиле ТопПульт (issue №9) проверен на Linux с Python 3.15 и Node.js:

```bash
python -m unittest discover -s tests -p test_dashboard.py -v
```

Все 28 тестов панели проходят. `DemoDataTest` проверяет, что демо заполняет все вкладки. Класс `TopPultInterfaceTest` проверяет:

- шапку, подвал и список проектов с итогами; предупреждение и блокировку сбора
  при нулевом балансе;
- форму создания проекта с дополнительными настройками;
- вкладки проекта и паузу;
- редактирование мощности и переходов, а также «Авто-стратегию»;
- дерево кластеров и перекластеризацию;
- импорт CSV переходов с фильтрами брендовых и удалённых запросов;
- данные графика, матрицу и CSV-экспорт позиций;
- ежедневный автоматический сбор и пропуск редких низкочастотных фраз.
- регрессии после ревью: CSV-экспорт переходов со всеми строками и защитой
  от формул, отказ 422 на дату вне диапазона, перекластеризацию фраз без замера
  за последний день, выключенный автосбор у проектов из старой базы, повтор
  отложенного автосбора не чаще раза в 30 минут и пустую мощность без
  подстановки 10.

Тест `test_position_class_filter_and_js_agree` сравнивает Jinja-фильтр
`position_class` с функцией `positionClass` из `dashboard/static/positions.js`
в Node.js.

Скриншоты `docs/screenshots/issue9-*.jpg` сняты в Playwright Chromium
(1440×900 и 390×844) по демо-данным. Консоль браузера ошибок не показала.
Сценарий съёмки:

```bash
python -m examples.dashboard_demo --port 8091
NODE_PATH="$(npm root -g)" node experiments/issue9_screenshots.js http://127.0.0.1:8091 docs/screenshots
```

Поведение формы в браузере проверяет `experiments/issue9_form_js.js`: скрытые
поля своего региона отключаются и не блокируют отправку, а поле бренда
перестаёт быть обязательным, когда заданы брендовые запросы.

```bash
NODE_PATH="$(npm root -g)" node experiments/issue9_form_js.js http://127.0.0.1:8091
```

`tests/test_agent.py` в этом окружении не импортируется без DrissionPage.
На ветке `main` эта ошибка возникает так же.

## Проверка для PR №7

На Linux с Python 3.15 и Chrome 155 прошли все 32 теста:

```bash
python -m unittest discover -s tests -v
```

Тестовый HTTP-сервер воспроизводит выдачу с разным количеством результатов на
странице, переход к уточнённому запросу, пустую выдачу, SmartCaptcha и HTTP 429.
Тест `test_rank_agent_reads_database_and_stores_report` читает результаты и
журнал браузерного прогона из SQLite. Другие тесты проверяют вызов Docker с
общими путями, сохранение позиций из старой базы, границы суток МСК, независимые
измерения двух типов запросов и поля кластеров. DrissionPage выводит прежние
предупреждения `ResourceWarning` о дескрипторах подпроцессов.

В Playwright рабочая панель открылась с пустой базой. После создания проекта
кнопка «Снять позиции» запустила Chromium на `:1` и записала в SQLite семь
прочитанных страниц локальной выдачи и третью позицию по запросу с подсказкой.
Журнал каждого прогона и последний `report.json` открылись в панели.
В отдельном демо проверены четыре представления, переключение процентов и
количества на графике, исходные и уточнённые запросы, матрица дат и прокрутка
таблиц при ширине 390 пикселей.

В Linux через Xvfb и noVNC видно окно Chromium с локальной выдачей. При одиночном
запросе к `ya.ru` появилась SmartCaptcha. Парсер завершился после первой
страницы со статусом `CAPTCHA` и `captcha_encountered: true`. Проверка успешного
разбора живой выдачи и запуска в Windows Docker Desktop остаётся открытой.

## Проверка для PR №6

На Linux с Python 3.12 и Chromium прошли 27 тестов из `tests/`.
Новые проверки покрывают пустую рабочую базу, миграцию старых позиций,
раздельные измерения по исходным и уточнённым запросам, отображение
журнала и дат МСК, сохранение отчёта до закрытия окна и остановку на SmartCaptcha.
При возврате по истории тест воспроизводит временный ответ Chromium
`Not attached to an active page`. Ожидание продолжает опрашивать страницу в
пределах заданного времени. DrissionPage по-прежнему выводит `ResourceWarning`
при запуске некоторых тестов.

В Playwright проверены создание проекта с чистой базой, блокировка запуска
без реквизитов API, семь колонок таблицы позиций и горизонтальная прокрутка
на мобильной ширине. Съём позиций проверен с тестовыми ответами Yandex Search
API. Рабочие реквизиты API для проверки недоступны.

В Linux на `DISPLAY=:1` через noVNC проверены ввод запроса, отправка формы,
переход из локальной выдачи и прокрутка. Панель отобразила созданный агентом
отчёт с МСК, селектором, `scrollY=1200` и сбоями HTTP 404 и 503. Проверка в
Windows Docker Desktop и переход из живой выдачи остаются открытыми.

## Повторная проверка для PR №3

На Linux с Python 3.12.3, Chrome 155 и зависимостями из `requirements.txt`
контрольный пример `hello_world.py --local` под Xvfb вывел
`local-pf Chromium check` и завершился с кодом 0. Все 15 автоматических
тестов прошли. DrissionPage вывел предупреждения `ResourceWarning` о
подпроцессах при запуске тестов, как и при предыдущей проверке.

```bash
xvfb-run -a python3.12 examples/hello_world.py --local
python3.12 -m unittest discover -s tests -v
xvfb-run -a python3.12 agent.py
```

При одиночном запуске с конфигурацией из репозитория форма на `ya.ru`
открылась и агент отправил запрос. После отправки появилась SmartCaptcha.
Агент завершился с кодом 1 и записал в `report.json`
`captcha_encountered: true`, `search_result_found: false` и
`pages_checked: []`. Переход из живой выдачи и серия из 10–20 сценариев
остаются открытыми. Проверка Windows Docker Desktop и noVNC относится к
этапам 1 и 3 инструкции.

## Предыдущая проверка в контейнере

Контейнер `dp-agent` создан из образа `qiudeng/drissionpage4-ubuntu-webdesktop-novnc`
с монтированием проекта в `/app`. В образе Google Chrome 122.0.6261.128 и Xvfb на
`:1`. Зависимости установлены в отдельное окружение CPython 3.11.18.
HTTP-интерфейс noVNC на порту 56565 ответил. Хост проверочного запуска — Linux.

```powershell
docker exec -w /app dp-agent /opt/local-pf/bin/python -m unittest discover -s tests -v
docker exec -e DISPLAY=:1 dp-agent /opt/local-pf/bin/python /app/agent.py
```

Для автоматической проверки тестовый HTTP-сервер имитирует форму поиска, выдачу
и целевой сайт. Поиск и сайт используют разные имена хоста. Проверка HTTP-запросов
подтверждает, что Chromium отправил поисковую форму, получил страницу выдачи,
перешёл с неё на целевой сайт, перешёл с сайта на нужную страницу и пролистал её.
Проверка также читает файл `report.json`.

В контейнере прошли 14 сценариев. После исправления прав JSON на
смонтированной папке отдельно повторены сквозной сценарий и модульные проверки,
включая сравнение прав доступа отчёта и журнала. Файл отчёта прочитан с Linux-хоста.
DrissionPage выводит `ResourceWarning` при запуске Chrome под `unittest`.
После прогона активных процессов Chrome в контейнере не осталось.

Команда запуска агента с `DISPLAY=:1` вернула код 1. Яндекс показал
SmartCaptcha до отправки запроса. В отчёте `captcha_encountered: true`,
`search_result_found: false`, `pages_checked: []`. Клик по живой выдаче
через noVNC и серия из 10–20 запусков на реальных сайтах остаются непроверенными.

## Сценарии из ТЗ

| Сценарий | Проверка |
| --- | --- |
| Поиск и переход на целевой сайт | Локальные страницы, переход по клику в текущей и новой вкладке, проверка JSON и событие пролистывания. Реальную выдачу нужно подтвердить отдельным запуском с доступной формой поиска. |
| SmartCaptcha | Покрыто обнаружение по адресу, скрытому полю и форме проверки с HTTP 403. Агент останавливается с кодом 1, сохраняет `captcha_encountered: true` и не открывает целевой сайт. Прохождение SmartCaptcha остаётся открытым критерием. |
| Целевой сайт отсутствует | Код 1, `search_result_found: false`. |
| Целевая страница отсутствует | `NOT_FOUND` для отсутствующей ссылки, HTTP 404 и отсутствия ожидаемого элемента. Проверка следующей страницы продолжается. |
| Прокси недоступен | Интеграция прокси для обхода блокировок остаётся открытым критерием. Сетевой обрыв на целевой странице проверяется отдельно с результатом `NETWORK_ERROR`. |
| SmartCaptcha не пройдена с трёх попыток | Автоматические попытки решения и порог успешности 8 из 10 остаются открытыми критериями. При появлении проверки агент останавливается. |

Дополнительно проверены HTTP 503, таймаут после клика, остановка на HTTP 403 и 429,
границы совпадения домена, история вкладок и предел в два перезапуска после
отключения Chromium. Проверка перезапусков использует имитацию сбоя.

Агент использует обычный ввод и клики Chromium. Имитация набора для маскировки
автоматизации и параметры сокрытия автоматизации остаются открытыми требованиями.
